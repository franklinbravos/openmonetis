Feature central de lançamentos. CRUD de transações, pagamentos, parcelas e antecipações, refound, split, importação (arquivos/PDF/extrato), anexos de transação, exportação e a tabela/página de lançamentos. É o núcleo consumido por outras páginas (fatura, extrato, calendário, inbox).

## Summary

- actions.ts — barrel das Server Actions de transações
- actions/core.ts — ações centrais (criar/editar/excluir transações); validação de limite do cartão (`validateCardLimit`) via RPC `get_card_open_amount`
- actions/single-actions.ts — ações unitárias (settle, unlink, etc.)
- actions/bulk-actions.ts — ações em lote (marcar pagas, categorizar, deletar)
- actions/anticipation.ts — antecipação de parcelas
- actions/attachments.ts — anexar arquivos a transações; contagem de vínculos de anexo via RPC (`get_attachment_remaining`, `get_attachments_remaining_counts`) com escopo por `userId`
- actions/export-actions.ts — exportação de lançamentos
- actions/import-action.ts — processamento de importação
- actions/import-source-action.ts — registro de fonte de importação
- actions/import-batch-history-action.ts — histórico de batches de importação
- actions/parse-import-pdf-action.ts — extração de dados de PDF de fatura
- actions/fetch-by-id.ts — busca de transação por id (para dialogs)
- actions/fetch-dialog-options.ts — opções dos dialogs (categorias, pagadores, etc.)
- actions/refund-action.ts — lançamento de estorno
- actions/category-memory-action.ts — memória de categorização (reuso de categoria por estabelecimento)
- actions/core.test.ts — testes de regras centrais
- queries.ts — portas de leitura (fetchTransactions, fetchTransactionsPage, filtros, opções); `fetchRecentEstablishments` via RPC (`get_recent_establishments`); as contagens de paginação de `fetchTransactionsPage`/`fetchTransactionsPageWithRelations` permanecem no bridge (exceção documentada)
- queries/import-batch-history.ts — leitura de histórico de importações
- queries/import-source.ts — leitura de fontes de importação
- components/page/transactions-page.tsx — página de lançamentos (tabela + filtros + toolbar)
- components/table/ — tabela de lançamentos (colunas, filtros, paginação, actions menu, mobile list, bulk bar)
- components/dialogs/transaction-dialog/ — dialog completo de criação/edição (seções básica, boleto, categoria, condição, nota, pagador, pagamento, split)
- components/dialogs/ — outros dialogs (detalhes, bulk action, bulk import, mass add, refund, split pair, antecipação)

- components/attachments/ — seção de anexos do dialog de transação

- components/shared/ — components compartilhados da feature (anticipation card, establishment input, installment timeline)
- components/select-items.tsx — opções reutilizáveis de seleção
- components/transactions-export.tsx — botão/fluxo de exportação
- components/transactions-import-button.tsx — botão de importar
- components/types.ts — tipos de UI da feature
- hooks/use-installment-anticipations.ts — estado das antecipações

- lib/page-helpers.ts — helpers de filtros/paginação compartilhados por várias features (calendar, inbox, reconciliation, fatura, extrato)

## Constraints

- Toda query deve filtrar por `userId` (+ `adminPayerId` via `getAdminPayerId` quando o domínio envolver pagadores).
- Ações de mutation chamam `revalidateForEntity("transactions", userId)` (e entidades relacionadas).
- Valores monetários em `numeric(12,2)`; parse/format via `src/shared/utils/currency.ts`.
- Importações são parseadas por `src/shared/lib/import/*` (CNAB/OFX/PDF/XLS/CSV) e persistidas em batches.

## Guidance

- Outras features reutilizam `queries.ts` e `lib/page-helpers.ts` deste módulo — alterá-los exige checar consumidores (calendar, inbox, invoices, accounts/statement, reconciliation).
