Feature do painel inicial (dashboard). Compõe o grid de widgets editável com métricas do período, contas, faturas, contas a pagar, notas, pessoas, anexos, inbox, distribuição por categoria, etc. `fetch-dashboard-data.ts` centraliza a busca de todos os dados com cache por `userId` + período.

## Summary

- fetch-dashboard-data.ts — fetcher principal (cached `"use cache"`, tag `dashboard-${userId}`) que agrega todas as queries do dashboard
- page-data-queries.ts — busca dados da página (dashboardData + preferências + opções de quick actions)
- bills/ — queries/helpers/controller do widget de contas a pagar
- categories/ — queries e helpers de breakdown/histórico por categoria (overview e histórico via RPCs `get_category_overview`/`get_category_history`; total anterior do detalhe via `get_category_previous_total`)
- expenses/ — queries e helpers de despesas recorrentes, por categoria, top expenses, análise de parcelas
- goals-progress/ — queries/helpers/controller do widget de metas por categoria
- invoices/ — queries/helpers/controller do widget de faturas; agregações via RPCs `get_dashboard_invoices` e `get_invoice_payer_breakdown` (Supabase)
- notifications/ — actions e queries de notificações do navbar; faturas atrasadas/do período e orçamentos via RPCs `get_overdue_invoices`, `get_period_invoice_totals` e `get_budget_spent` (boletos e estados persistem como select simples no bridge)
- overview/ — queries de métricas e overview do período (receitas/despesas/saldo); agregações via RPC `get_period_overview`
- payments/ — queries e helpers de condições/métodos de pagamento e status de pagamento
- lib/ — queries auxiliares (contas, pessoas, inbox snapshot, navbar, top estabelecimentos, preferências, filtros, logos)
- lib/accounts-queries.ts e lib/navbar-queries.ts — saldo de contas e cards do navbar via RPCs `get_account_balances` e `get_navbar_cards` (Supabase); fallback de contas sem movimentações via `src/shared/lib/accounts/queries.ts` quando não há pagador admin
- widget-registry/ — registro e actions de configuração de widgets
- components/dashboard-grid-editable.tsx — grid de widgets arrastável/ordenável
- components/dashboard-metrics-cards.tsx — cards de métricas (receitas, despesas, saldo)
- components/dashboard-quick-actions.tsx — ações rápidas (adicionar lançamento, transferência, etc.)
- components/dashboard-welcome.tsx — mensagem de boas-vindas
- components/bills/ — view do widget de contas a pagar
- components/category-breakdown/ — view do widget de breakdown por categoria
- components/goals-progress/ — view do widget de metas
- components/installment-analysis/ — página de análise de parcelas (usada por reports/installment-analysis)
- components/installment-expenses/ — view do widget de despesas parceladas
- components/invoices/ — view do widget de faturas
- components/notes/ — view do widget de anotações
- components/payment-overview/ — views de condições/métodos de pagamento
- components/payment-status/ — view do widget de status de pagamento
- components/widgets/ — componentes de cada widget disponível no grid

## Constraints

- O cache do dashboard é invalidado pela tag `dashboard-${userId}` via `revalidateForEntity` (entidades financeiras).
- Sempre filtrar por `userId` e, quando aplicável, pelo período selecionado.
- Agregações de categorias (breakdown, metas, histórico) vêm de RPCs do Supabase (`SECURITY DEFINER`, `p_user_id`); selects simples continuam no bridge.
- Agregações de pessoas (`lib/payers-queries.ts`) e do snapshot de inbox (`lib/inbox-snapshot-queries.ts`) via RPC functions do Supabase (nativas em SQL, `SECURITY DEFINER`, filtro `p_user_id`); selects simples via bridge.
