Feature de relatórios. Queries e componentes para os relatórios de tendências de categoria, uso de cartões, estabelecimentos e análise de parcelas. Cada relatório tem sua rota em `src/app/(dashboard)/reports/`.

## Summary

- components/category-report-page.tsx — página do relatório de categoria (tendências)
- components/category-report-*.tsx — cards, chart, export, filters, table do relatório de categoria
- components/category-table.tsx / category-cell.tsx — tabela/célula de categoria
- components/types.ts — tipos de UI dos relatórios
- components/cards/ — componentes do relatório de uso de cartões (overview, breakdown, invoice status, top expenses, usage chart)
- components/establishments/ — componentes do relatório de estabelecimentos (list, highlights, summary, top categories, period filter)
- lib/category-report-queries.ts — dados do relatório de categoria (agregação via RPC `get_category_totals` com `p_use_abs=false`; `buildCategoryReportData` é função pura testada)
- lib/category-chart-queries.ts — dados de chart por categoria (agregação via RPC `get_category_totals` com `p_use_abs=true`)
- lib/category-trends-queries.ts — categorias do usuário para tendências
- lib/cards-report-queries.ts — dados do relatório de uso de cartões (agregações via RPC; selects simples via bridge)
- lib/utils.ts — validação de intervalo de datas
- establishments/queries.ts — dados de top estabelecimentos (agregações via RPC; selects simples via bridge)
- establishments/queries.test.ts — testes do mapper puro `buildEstablishments`

## Constraints

- A análise de parcelas (`installment-analysis`) é implementada por `features/dashboard/expenses/installment-analysis-queries.ts` + componente em `features/dashboard/components/installment-analysis/`.
- Queries sempre filtram por `userId` (+ `getAdminPayerId` quando envolve pagadores).
- Agregações de categorias usam a RPC `get_category_totals` (`p_use_abs` controla soma absoluta vs. valor); selects simples continuam no bridge.
- Agregações (sum/count/groupBy) de estabelecimentos e cartões usam RPC functions do Supabase (definidas em `supabase/migrations/20260810000400_rpc_reports.sql`) via `callRpc`; seleções simples continuam no bridge. `get_top_categories` preserva `ORDER BY total_amount ASC` (ordem ascendente original de `establishments/queries.ts`).
