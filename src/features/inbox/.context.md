Feature de pré-lançamentos (inbox). Recebe itens de notificações bancárias do app OpenMonetis Companion via `src/app/api/inbox/*`, exibe para revisão e converte em lançamentos (ou descarta). É o ponto de entrada do fluxo Companion → app.

## Summary

- actions.ts — Server Actions do inbox (aprovar→criar lançamento, descartar, manter)
- queries.ts — leituras (fetchInboxItemsPage, counts por status, fontes, dialog data)
- page-helpers.ts — resolução de search params (status, paginação, source app)
- components/inbox-page.tsx — página do inbox
- components/inbox-tabs.tsx — abas por status
- components/inbox-items-list.tsx — lista de itens
- components/inbox-card.tsx — card do item
- components/inbox-details-dialog.tsx — dialog de detalhes (pré-preenche o dialog de lançamento)
- components/inbox-bulk-actions.tsx — ações em lote
- components/inbox-pagination.tsx — paginação
- components/types.ts — tipos de UI (InboxItem, InboxStatus, etc.)

## Constraints

- Itens chegam via API com autenticação por Bearer token (`apiTokens`) e rate limit (100 req/min, 20 req/min no batch).
- Schema de entrada validado por `src/shared/lib/schemas/inbox.ts`.
- Aprovar um item cria um lançamento e atualiza o status do item.
- Mutation chama `revalidateForEntity("inbox", userId)`.
- Contagens de status e do pending count usam RPC functions do Supabase (`get_inbox_status_counts`, `get_inbox_count` — `SECURITY DEFINER`, filtro `p_user_id`); selects de itens e fontes seguem no bridge.
