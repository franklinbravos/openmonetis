Feature de pessoas (pagadores). CRUD de pessoas, compartilhamento de acesso (convites, roles admin/editor/viewer, sair do compartilhamento) e página de detalhe da pessoa com histórico, uso de cartões, métodos de pagamento e resumo mensal. Na UI o termo é "pessoa"; código/schema usam `payer`/`payerId`/`adminPayerId`.

## Summary

- actions.ts — Server Actions de pessoas
- actions/share-access.ts — actions de compartilhamento (aceitar, revogar, mudar role, sair)
- queries.ts — leituras (fetchPayersForUser)
- lib/avatar-options.ts — opções de avatar
- lib/build-readonly-option-sets.ts — option sets readonly para visualização
- lib/detail-actions.ts — ações do detalhe da pessoa
- lib/detail-queries.ts — queries do detalhe (histórico, resumo mensal, uso de cartões)
- lib/share-invites.ts — lógica de convites de compartilhamento
- components/payers-page.tsx — página de pessoas
- components/payer-card.tsx — card de pessoa
- components/payer-dialog.tsx — dialog de criação/edição
- components/payer-select-items.tsx — opções de seleção de pessoa
- components/types.ts — tipos de UI
- components/details/ — cards do detalhe (info, histórico, resumo mensal, uso de cartões, métodos de pagamento, sharing, acesso, leave-share)

## Constraints

- O admin do usuário é descoberto via `getAdminPayerId(userId)` de `src/shared/lib/payers/get-admin-id.ts` — nunca JOIN direto.
- Lógica de acesso/roles/permissões e convites em `src/shared/lib/payers/` (access, share-permissions, share-code, share-invite-queries).
- Mutation chama `revalidateForEntity("payers", userId)`.
