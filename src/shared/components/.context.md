Componentes de UI reutilizados entre features. Inclui primitivas shadcn/ui, navegação (navbar), providers de contexto, marca (logos), widgets, feedback, month-picker, logo-picker, calculator, entity-avatar e skeletons.

## Summary

- ui/ — primitivas shadcn/ui (button, dialog, input, select, table, tabs, tooltip, etc.)
- navigation/ — navegação do app: navbar (app-navbar, nav-items, notification-bell) e page-breadcrumb
- navigation/navbar/notification-bell/ — sino de notificações com subcomponentes
- providers/ — providers de React (theme, query, app-preferences, privacy, logo-dev, supabase-auth-listener)
- brand/ — logos do app (logo, logo-icon, logo-text)
- widgets/ — widget-card, widget-empty-state, expandable-widget-card
- feedback/ — empty-state, payment-success, status-dot
- month-picker/ — navegação de períodos (month-navigation, statement-period-navigation, use-month-period, period-carousel-types)
- logo-picker/ — seletor de logo de estabelecimento
- calculator/ — dialog de calculadora (display, keypad)
- entity-avatar/ — avatares/ícones de entidades e logo de estabelecimento
- skeletons/ — skeletons de loading (tabela, dashboard, extrato, fatura, widget, etc.)
- animated-theme-toggler.tsx — alternador de tema animado
- confirm-action-dialog.tsx — dialog de confirmação genérico
- money-values.tsx — formatação de valores monetários em componentes
- page-description.tsx — cabeçalho padrão de página (ícone + título + subtítulo)
- period-picker.tsx — seletor de período
- refresh-page-button.tsx — botão de refresh
- transaction-type-badge.tsx — badge de tipo de transação

## Constraints

- Primitivas shadcn/ui não devem ser estendidas com lógica de domínio — componentes de domínio vão para as features.
- Providers que dependem de sessão/domínio específico devem ser mantidos mínimos e agnósticos.
