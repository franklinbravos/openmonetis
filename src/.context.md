Raiz do código do OpenMonetis. Segue arquitetura feature-first: rotas e páginas finas em `app/`, código de domínio por feature em `features/`, código genuinamente reutilizado em `shared/`, schema do banco em `db/`. UI em português (pt-BR), pastas/imports em inglês.

## Summary

- app/ — rotas do Next.js App Router: layouts, páginas finas, loading states, rotas de API e metadata
- features/ — código de domínio por feature (transactions, cards, accounts, payers, etc.)
- shared/ — componentes, hooks, lib e utils reutilizados entre features
- db/ — schema.ts do banco (Drizzle ORM)
- proxy.ts — middleware Next.js com CSP e proteção de rotas autenticadas
- global.d.ts — declarações globais de tipos

## Constraints

- Sempre filtrar queries por `userId`; nunca cruzar dados de usuários diferentes.
- Descobrir o pagador admin via `getAdminPayerId(userId)` de `src/shared/lib/payers/get-admin-id.ts`, nunca via JOIN direto.
- Períodos usam formato `YYYY-MM` (utils em `src/shared/utils/period/`).
- Moeda: R$ com 2 casas decimais, DB `numeric(12, 2)` (utils em `src/shared/utils/currency.ts`).
- Revalidar após mutations com `revalidateForEntity("entity", userId)` de `src/shared/lib/actions/helpers.ts`.
- Features não importam outras features. Exceção intencional e aceita: `features/attachments` importa `TransactionDialog`, `TransactionDetailsDialog` e `TransactionItem` de `features/transactions`.
- "Pagador" é exibido como "pessoa" na UI, mas código/schema/rotas mantêm `payer`/`payerId`/`adminPayerId`. Não renomear.

## Guidance

- `AGENTS.md` na raiz é a fonte autoritativa de arquitetura e convenções — consultar antes de mudanças estruturais.
- Importar apenas por `@/app|features|shared|db/...`; nunca por caminhos relativos longos.
