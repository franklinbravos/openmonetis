Schema do banco de dados (Drizzle ORM + PostgreSQL). Arquivo único `schema.ts` com todas as 30 tabelas e relations. As tabelas `user`, `account`, `session`, `verification` e `passkey` são remanescentes do Better Auth; a autenticação em produção usa Supabase Auth.

## Summary

- schema.ts — definição de todas as tabelas e relations (Drizzle)

Tabelas: `user`, `account`, `session`, `verification`, `passkey` (legado Better Auth), `userPreferences` (tabela `preferencias_usuario`), `financialAccounts` (tabela `contas`), `categories`, `payers`, `payerShares`, `payerShareInvites`, `cards`, `invoices`, `budgets`, `notes`, `savedInsights`, `apiTokens`, `inboxItems`, `dashboardNotificationStates`, `installmentAnticipations`, `transactions`, `attachments`, `transactionAttachments`, `noteAttachments`, `importBatches`, `importCategoryMappings`, `reconciliationSessions`, `reconciliationLines`, `reconciliationAliases`, `establishmentLogos`.

## Constraints

- Campos de moeda são `numeric(12, 2)`.
- Mudanças de schema exigem `pnpm run db:generate` e registro no `CHANGELOG.md`.
- Novos campos de user data devem respeitar o padrão de filtro por `userId`.

## Guidance

- Tabelas de auth (user/account/session/verification/passkey) não devem ser alteradas sem revisar o impacto no Supabase Auth.
- Nomes de tabela legados em português (`preferencias_usuario`, `contas`) são mantidos; não renomear sem migração planejada.
