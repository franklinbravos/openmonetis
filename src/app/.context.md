Rotas do Next.js App Router. Contém apenas roteamento, layouts, loading states, páginas finas (que buscam dados e delegam renderização às features), rotas de API e metadata. A lógica de domínio vive em `src/features/`, nunca aqui.

## Summary

- (auth)/ — páginas de login, cadastro e convite, mais o callback OAuth do Google
- (dashboard)/ — área autenticada: páginas finas por feature + layout com navbar
- (landing-page)/ — página pública de marketing/landing
- api/ — rotas de API (auth, inbox, transactions, logo, insights, attachments, health)
- auth/callback/ — rota de callback do Supabase Auth
- layout.tsx — root layout: ThemeProvider, QueryProvider, SupabaseAuthListener, Toaster
- globals.css — estilos globais (Tailwind 4)
- error.tsx — error boundary global
- not-found.tsx — página 404
- robots.ts / sitemap.ts / manifest.json — metadata e SEO
- apple-icon.png / icon1.png / favicon.ico — ícones do app

## Constraints

- Páginas devem ser finas: `getUser()`/`getUserId()`, chamar a query/feature, renderizar o componente da feature.
- Layouts, `loading.tsx` e metadata permanecem aqui; componentes de UI vão para as features.
- Rotas em `api/` protegidas exigem `getUser()` ou `getOptionalUserSession()` antes de qualquer lógica, retornando 401.
- Não importar código de `src/app` de fora — features não dependem de rotas.

## Guidance

- Nomes de rotas seguem a tabela Português→English do `AGENTS.md` (ex: `lancamentos`→`transactions`, `cartoes`→`cards`).
