Rotas de API do Next.js. Exponem endpoints HTTP para auth (login/logout/OAuth), recebimento de pré-lançamentos do app Companion (inbox), consultas de logo/insights, presign de uploads de anexos e health check.

## Summary

- auth/login/ — POST login por e-mail/senha (Supabase Auth)
- auth/logout/ — POST logout
- auth/google/ — inicia Google OAuth
- auth/google/setup/ — auxiliar de setup do OAuth
- auth/device/ — tokens de API para dispositivos (listagem, revogação)
- auth/device/tokens/ — CRUD de tokens por dispositivo
- auth/device/tokens/[tokenId]/ — operação em token específico
- auth/device/verify/ — verificação de token de dispositivo
- inbox/ — POST de pré-lançamento vindo do Companion (auth por Bearer token, rate limit 100 req/min)
- inbox/batch/ — POST em lote de pré-lançamentos (rate limit 20 req/min)
- insights/saved/ — CRUD de insights salvos
- logo/search/ — busca de logos de estabelecimentos
- logo/mapping/ — mapeamentos de logos
- transactions/ — transações por API (consulta)
- transactions/[transactionId]/ — operação em transação específica
- transactions/installments/[seriesId]/ — consulta de parcelas de uma série
- transactions/installments/[seriesId]/anticipations/ — antecipações de parcelas
- transactions/[transactionId]/attachments/ — anexos de uma transação
- attachments/[attachmentId]/presign/ — gera URL assinada de upload de anexo
- health/ — health check para Docker/monitoramento (consulta Supabase RPC)

## Constraints

- Rotas protegidas exigem `getUser()` ou `getOptionalUserSession()` e retornam 401 quando não autenticadas.
- Rotas com IDs de recursos devem verificar ownership via `eq(table.userId, userId)`.
- Não remover rate limiting existente (inbox/batch) nem reduzir limites.
- Nunca expor stack traces/paths ao cliente; mensagens genéricas "Algo deu errado".
